# Longer hourly research history

The offline importer accepts the extracted official-format `XBTUSD_60.csv`: seven headerless columns `timestamp,open,high,low,close,volume,trades`, with Unix-second timestamps. Consult [Kraken's official historical OHLCVT page](https://support.kraken.com/articles/360047124832-downloadable-historical-ohlcvt-open-high-low-close-volume-trades-data) for the available download archives. The importer does not download archives, unzip arbitrary inputs, or write to the live observation database.

Run `python backend/scripts/import_kraken_history.py --csv /absolute/path/XBTUSD_60.csv --output /absolute/research/output --source-url https://support.kraken.com/articles/360047124832-downloadable-historical-ohlcvt-open-high-low-close-volume-trades-data`. Default minimum is 365 days of contiguous completed hourly candles. `--minimum-days` explicitly permits shorter research samples. A year is 8,760 hourly records, not an assumed calendar-year leap rule.

Strict validation rejects incorrect filenames, headers, missing/duplicate/unordered hours, future/incomplete intervals, nonfinite or negative data, inconsistent OHLC and unsupported precision. It never fills missing hours. Sparse old history must be independently investigated and a documented contiguous research interval selected; renaming another instrument is not a valid correction. The bounded CSV size is 64 MiB, sufficient for many years of hourly data.

To select a modern contiguous interval from an archive with early no-trade gaps, add `--start 2023-01-01T00:00:00+00:00 --end 2026-01-01T00:00:00+00:00`. Both explicit timezone-aware hourly bounds are required; start is inclusive and end exclusive. Every raw row still receives numerical/OHLC/alignment validation, but gaps outside the chosen interval are ignored. Missing boundary candles or any gap/duplicate inside the interval fail closed. Exact selection bounds are included in the content identity and manifest; no candles are invented or silently trimmed inside the requested window.

Output is a new content-addressed directory with `dataset.csv` and `manifest.json`. It records raw-input and canonical-output hashes, exact identity, span, import timestamp and explicit source claim. Existing snapshots cannot be overwritten. `load_history_bundle(directory)` verifies identities, hashes, regular-file bounds and temporal/content validation before returning a frame and manifest. No executable serialization is loaded.

`merge_verified_history(history_frame, live_candle_rows, as_of=...)` accepts already-persisted `CryptoCandle` rows, verifies their recorded integrity/freshness/availability, requires at least one exact OHLCV overlapping candle and rejects discrepancies or any gap. The importer optionally includes these rows with their provenance hashes. This creates a separate research artifact, never inserts archive records into the forward-observation ledger.

Checksums establish consistency, not source authentication. The filename/source page is a caller claim; the manifest explicitly records `provenance_authenticated=false` and `eligible_for_qualification=false`. Historical initialization cannot establish genuine forward performance or authorize live trading. No historical archive was downloaded as part of this implementation.
