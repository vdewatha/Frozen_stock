# Isolated forward paper comparison

`advance_comparison(path, candles, observed_at=..., ml_probability=None, ml_expected_net=None, config=ComparisonConfig(...))` uses a dedicated SQLite file, never the live database. It refuses a database containing unrelated tables. The complete policy, model identifier and cost assumptions are hashed and frozen on first use; changed configuration requires a new comparison database.

Five independent virtual accounts each start with $10,000: 20/50-hour trend, 14-hour RSI mean reversion, cost-aware ML, cash, and fixed-$100 buy-and-hold. Default order budget is $100, including costs; there is no shorting or pyramiding. Baseline assumptions are 0.8% fees and 0.1% slippage per side. A stress configuration can explicitly set 1% fees and 0.2% slippage. These are simulation assumptions, not a promise of available fees or liquidity.

Inputs must be verified, contiguous, completed Kraken BTC/USD hourly candles observed within five minutes of the latest close. Production callers must provide real wall time. At the first step a policy can only queue a decision; it cannot fill. A queued order fills at the next newly observed consecutive hourly candle-close proxy, with explicit costs. This is not a historical next-open fill and not a verified executable quote. A missed hour cancels pending orders instead of creating backfilled trades. Repeated calls for a recorded hour are idempotent; conflicting market-data hashes fail closed.

The ML adapter must validate model artifacts, costs, distribution checks and calibration before passing a probability and expected net return. An ML entry requires the frozen probability threshold plus expected net return above the frozen margin. Missing values produce `model_unavailable` and cancel queued ML buys; no probability is invented. Exit occurs on low probability or at the configured holding horizon, with the same next-observation simulation delay. Model-unavailable positions still retain their horizon exit.

Each step durably records decisions, explanations, input/model/config hashes, simulated fills, costs, balances, mark-to-market equity and peak drawdown. Exceeding the drawdown threshold halts future entries and queues an exit; it is not a guaranteed maximum loss because execution waits for another observed price. Cash and buy-and-hold benchmarks use the same capital and fixed exposure budget. Reports explicitly remain nonqualifying simulated outcomes, not realized brokerage P&L, model promotion or live authorization.
